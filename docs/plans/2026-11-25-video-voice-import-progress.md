# 视频提取音色与独立页面升级记录

日期：2026-11-25。

## 已实现

- 独立 `/voices` 页面：首页与编辑器有入口，编辑器新标签打开并在返回焦点时刷新音色，不改课程草稿。
- 视频/录音最大 200 MB，选择 3～30 秒参考片段，流式上传、提取单声道 24k WAV、本地 SenseVoice 自动识别。
- 提取结果可试听、识别原文可校对，确认后命名保存音色。最近导入可找回；事务保证重复或并发保存只有一个音色，并显示最终已保存的原文。
- 音色支持搜索、改名、停用及合成试听；保留手动 WAV/MP3 与原文添加方式。
- 上传中断、超限和未入队失败只清理该次确切源文件，不递归删除目录；入队后的失败记录保留。
- ASR 与 TTS 共享 CPU 运行环境及串行监督。ASR 原生异常/加载超时时可降级为仅 TTS，重启有上限；配音历史不受影响。

## 验证

- 应用测试 78/78；Python 测试 8/8；类型检查和生产构建通过。
- 真实 SenseVoice + ZipVoice：6 秒英语视频提取、识别、校对保存、课程配音及带声 MP4 导出通过，两轮识别链路用时约 1.3～1.8 秒。准确识别出测试参考开头的两句话。
- 对已有合成中文参考音运行真实识别，约 1.7 秒返回中文文字；不将此测试等同于准确率评测，可能漏字，页面始终提供试听和校对。
- 协议夹具验证：满队列在接收文件前拒绝且不创建新源文件、未知扩展、音轨缺失、草稿和音色分离、保存幂等、校对原文重载、课程复用及 MP4 音轨。
- FFmpeg 实测：正常指定片段、越界、伪装格式、无音轨、视频长但音轨短、缺时长元数据的流式 MKV。
- 页面操作实测：切换最近导入，修改名称与原文并保存，新增音色出现在右侧，刷新后保留校对文字。
- 进程身份测试：不同配置、不同用户、创建时间/PID 不符均拒绝结束；本机加载新服务成功。Python 模拟原生 ASR 异常后降级为仅 TTS 的恢复路径通过。

识别模型额外下载 163,002,883 字节，固定官方包与 SHA-256；没有安装新 Python 框架或调用付费厂商。模型、输入媒体、令牌、测试结果均位于被忽略的数据目录。

## 审查和取舍

一次独立只读审查，没有 Critical；重要问题已在一轮修复中处理，包含选区完整性、无时长流式容器、并发保存显示、进程身份、原生 ASR 退出恢复、未入队文件占用、底层错误泄露。另将离页丢失校对文字提升为重要问题，改用会触发未保存提示的导航；验证脚本按 DATA_DIR 定位真实服务，未留待处理的小问题。

实现决定：

1. 延续用户的连续开发授权，在 main 完成并上传，不再次等待确认；通过测试与独立审查控制风险。
2. 只识别选定的 3～30 秒参考片段，不转写整部视频；降低本机资源开销并保证原文与参考声音对应，用户需选择合适片段。
3. 保留已入队的失败记录及忽略的验证工作区，遵守禁止批量删除；占用额外磁盘。未入队失败只删除单个明确源文件。
4. 语音识别用本地 SenseVoice 复用现有环境；首次多下载约 163 MB，不新增云端费用，需人工检查识别原文。
5. 界面检索的通用媒体风格与本工作台不匹配，沿用现有绿色、字体和表单规范；不新增外部字体或大视觉依赖。
6. 模型验收使用明确标记的合成参考，不把测试样本加入用户音色库；真人音色相似度、主观音质和 ASR 准确率不由此证明。
