# 本地 ZipVoice 升级记录

日期：2026-11-25。

## 现在可做什么

- 当前课程选择腾讯云、MiniMax 或本地 ZipVoice，不改变其他课程。
- 上传 WAV/MP3 参考录音与准确原文，保存多个音色，支持改名、试听和停用。
- 将音色和语速应用到全部小节，单节或批量生成配音，继续试听和导出带声音 MP4。
- 独立 Python 环境运行 CPU 量化模型，首次下载后不调用云端配音 API；保留原腾讯云配置。
- 一条 PowerShell 命令启动网页、Worker 和已安装的引擎，复用已有进程并补启动缺失组件。

## 验证证据

- `npm test`：70 项通过。
- `python -m unittest discover -s tools/zipvoice`：4 项通过，包含超时子进程终止。
- `npm run typecheck`、`npm run build`：通过。
- 本机协议夹具：上传两个音色、改名、停用后禁止新试听、已排队试听继续、配音复用、过期音频禁止导出、有声 MP4 完整通过。
- 真实 ZipVoice 模型：同样完整流程通过，MP4 含视频和音频轨；使用系统离线合成的明确测试参考，不使用名人示例录音。
- 真实原生推理截止：0.1 秒测试预算触发模型进程终止，健康检查约 2.8 秒恢复，没有发布半成品。
- 网页检查：本地服务与音色下拉框可见，切到腾讯云后旧音频不算就绪，重新选择本地音色应用整片后可补齐并进入「可以导出视频」。网页文件选择器自动化中断，上传 API 的真实文件与错误输入测试已完成。
- 启动恢复：分别停止本任务管理的空闲 Web / Worker，启动脚本补启动缺失组件，保留另一个进程 ID，均通过。
- 验证脚本遇到已占用端口立即退出，不向已有工作台写入测试资料；自定义 DATA_DIR 的安装路径解析通过。

性能：i9-14900HX，约 31.7 GB RAM，4 线程 CPU。加载约 3 秒；101 字中文首次生成 38.78 秒、热生成 35.09 秒，音频约 18 秒；模型进程工作集约 791 MB。下载模型包、Vocos 与额外英文词典共约 170 MB，安装展开和运行环境另占磁盘。

## 审查与实现决定

独立审查没有 Critical 问题，发现的 10 项 Important 已修复：超时资源释放、配置错误片段泄露、格式伪装/截断音频、JSON 实际字节限制、异步上传选择竞态、配置等待时的音色编辑、停用音色与补齐范围、自定义数据目录、部分进程恢复、测试端口归属。

决定与影响：

1. 按用户授权在 main 连续执行，不再逐步等待确认；风险通过独立审查及回归验证控制。
2. 遵守禁止批量删除的规则，保留忽略的测试数据和执行工作区；会额外占用本机磁盘。
3. 下载期间先完成资料结构，安装和接口任务的提交适当合并；最终按完整链路验收。
4. 上传保存后由用户明确选择音色，不自动修改当前节，避免上传期间切换服务或重排小节时写错目标；多一次选择操作。
5. 真人音色的相似度、自然度及不同说话人区分度需要用真实录音试听，本次合成参考只证明技术链路；不能把真实模型接通等同于真人音质验收。
6. 未实际调用付费云厂商；云端兼容性以现有单元测试和本机协议测试验证，未消耗用户额度。

暂缓的小问题：切换到 MiniMax 时，音色输入框会显示内部占位值 `unselected`，用户需要手动选择建议或填写有效 ID。不会自动生成，也不影响本地 ZipVoice；后续可只改善占位文字。

模型、虚拟环境、录音、本机服务令牌和测试产物保存在被忽略的数据目录，不上传 GitHub。日常步骤固定维护在 `docs/操作指南.md`。
