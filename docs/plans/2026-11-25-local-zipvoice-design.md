# 本地 ZipVoice 配音与音色库设计

日期：2026-11-25

状态：设计待审阅，尚未实现或安装模型。

## 1. 做完后怎么用

你可以在项目中选择「本地 ZipVoice」，输入讲解稿，选一个已保存的音色，点击「生成此节配音」或「为全部小节生成配音」。生成的声音继续用于现有试听和 MP4 导出。

增加音色只需要做一次：打开「我的音色」→ 上传一段单人录音 → 填写录音里实际说出的文字 → 起名保存 → 输入一句话试听。以后直接从下拉列表选择。

**保存音色指保存参考录音和对应文字，不是为每个人训练一套模型。** 原录音里的声音特征会在每次生成时作为参考，因此两者必须一直保存在本机。

第一版保留腾讯云现有音色；本地音色库支持保存多个音色。没有本地音色时显示上传入口，不把模型包中的名人演示录音当成内置音色。第一版不另购或制作预置真人录音，用户上传两段录音即可得到两个可复用的本地音色。

## 2. 本次范围

包含：本地引擎安装与启动、音色上传/命名/试听/停用、项目内切换配音服务、单节与批量配音、试听与导出、操作指南更新。

暂不包含：自动识别参考录音文字、录音降噪、情绪控制、多人对话、训练新模型、浏览器端推理、远程部署或多人账号。

只要模型首次下载并安装成功，ZipVoice 的配音过程不需要调用云端 API。DeepSeek 写稿仍沿用原有服务。

## 3. 技术方案与选择理由

| 方案 | 好处 | 成本与限制 | 本次选择 |
| --- | --- | --- | --- |
| sherpa-onnx + ZipVoice-Distill INT8，CPU 推理 | 使用量化模型，避免安装完整 PyTorch；可保留参考音色 | 需要独立本地进程，速度需实测 | 采用 |
| 原版 ZipVoice + PyTorch | 便于深入调整模型 | 环境与依赖更重 | 暂不采用 |
| 继续只用腾讯云 | 已经接通，操作简单 | 受免费额度限制，不满足本地音色库目标 | 保留为手动可选项 |

本机已核对：Intel i9-14900HX（24 核、32 线程）、约 31.7 GB 内存、64 位 Python 3.11.7；尚未安装 sherpa-onnx。硬件信息不能代替模型实测，完成时必须报告冷启动、生成耗时和进程内存。

采用一个常驻 Python CPU 服务，加载一次模型，多次复用。初始使用 4 个推理线程和 4 步生成，线程数提供环境配置。Python 3.11 的 Windows x64 安装包必须先验证具备 ZipVoice API，再固定版本；不从源码构建、不改动现有 Anaconda 环境。

## 4. 页面和操作

「生成配音」阶段增加配音服务下拉框：腾讯云 / MiniMax / 本地 ZipVoice。选择保存到当前项目，不影响其他项目。旧项目未设置时沿用现有 TTS_PROVIDER。

「声音」面板根据当前服务显示其音色选项。本地模式下：

1. 音色下拉框显示所有启用的本地音色，首次必须明确选择；支持将音色和语速应用到全部小节。
2. 「管理音色」打开独立面板，可上传、改名、试听、停用。
3. 上传支持 WAV、MP3，最多 10 MB；解码后必须为 3～30 秒，建议 10～20 秒，无背景音乐、单人连续讲话。文字必填，最多 1,000 字。
4. 页面区分「服务未启动」「模型未准备好」「未选择音色」「等待生成」「生成失败」。失败显示原因及手动重试入口。
5. 更换文字、音色、语速或配音服务后，旧音频仍保留，但提示需要重新生成。不能把旧音频当作新设置的成品导出。

音色可改名，参考录音和参考文字保存后不可覆盖；需要更换时新建一个音色。停用后不再供新任务选择，历史音频和已排队任务仍可正常使用。项目引用了已停用音色时提示重新选择，不悄悄替换成其他声音。

现有腾讯云和 MiniMax 的生成方式不变。不同服务的音色不自动互相映射；切换后检查音色有效性，失效的小节要求重新选择。服务不可用时不自动转到其他厂商。

## 5. 组件之间怎么配合

```text
网页：选择服务、管理音色、编辑讲解稿
  ↓ Next.js API：校验、保存、创建任务
SQLite：项目 / 音色资料 / 配音任务 / 音色试听任务
  ↓ 现有单 Worker：依次处理任务
ZipVoice 适配器 → 本地 Python 服务 → WAV
  ↓
现有音频资产、播放器、Remotion 导出
```

### 服务与文件

- Python 服务代码放在 `tools/zipvoice/`；安装和启动脚本放在 `scripts/`，随仓库提交。
- Python 虚拟环境、模型、录音及生成结果放在已忽略的 `data/` 下，不上传 GitHub。
- 运行环境：`data/zipvoice/runtime/`；模型：`data/zipvoice/models/`。
- 标准化参考录音：`data/voices/<voiceId>/reference.wav`；生成的项目音频继续使用现有路径。
- 上传后用 FFmpeg 转为单声道、24 kHz、PCM WAV，以实际解码结果判断长度和有效性。不允许客户端指定服务器文件路径。
- 安装脚本只创建专用环境和下载固定版本文件，校验下载清单及 SHA-256；失败保留诊断信息，不递归清理文件。遵守项目禁止批量删除规则。

服务只监听 `127.0.0.1`，默认端口 8765，通过本机配置的随机令牌访问；浏览器只访问 Next.js API。模型下载、安装不是网页请求的副作用，由明确的初始化命令执行。

`GET /health` 返回模型是否加载及模型版本；`POST /synthesize` 接收文字、参考录音、参考文字和生成设置，返回 WAV。服务不接受任意远程 URL 或文件路径；参考录音由适配器读取后随请求发送，限制正文大小。

模型不放进 Next.js 进程。启动脚本隐藏启动本地服务，等待健康检查再标记可用，并记录自身进程信息。退出时只处理脚本创建且核对过身份的进程，不结束无关 Python 程序。

### 项目设置与任务

- 在 `Lesson` 增加可选 `speechProvider`，旧项目无须迁移；项目保存、AI 草稿应用、单节改写均保留该设置。
- 配音服务枚举显式增加 `zipvoice`。模型路由使用已知模型映射；历史 MiniMax 模型仍兼容，不能把 ZipVoice 误发给 MiniMax。
- 配音任务在入队时固定服务、模型版本、音色 ID、音色内容哈希、文本、语速。修改项目设置不改变已排队任务。
- 本地生成仍经过现有任务队列；音色试听使用独立试听任务表，由同一个 Worker 串行调度，页面轮询进度。一个 Worker 同时最多运行一次本地推理。
- 音色试听文字限制 200 字；课程讲解仍支持原有 3,000 字上限。长文本在适配器按句子拆分，每段最多 200 字，逐段生成后拼接为一个音频资产，不把参考录音拼入成品。
- 语速统一在生成后通过 FFmpeg `atempo` 调整，沿用页面 0.5～2 倍范围；最终 WAV 实测时长用于预览和导出。
- 单个本地任务限时 15 分钟，超时中止并标记失败，不发布半成品、不自动重试。服务崩溃或重启后，运行中的任务显示失败，待用户重试。

### 音色资料与缓存

SQLite 新增 `voice_profiles`：ID、名称、标准化录音相对路径、参考文字、录音时长、内容哈希、创建时间、停用时间。

音色 ID 与内容哈希稳定，改名不影响音色身份。合成缓存必须同时比较服务/模型版本、讲解稿、音色内容、语速。停用保留录音；不提供批量或物理删除。已经导出的快照和历史音频不受影响。

Web API：

| 接口 | 用途 |
| --- | --- |
| `GET /api/voices` | 列出音色及可用状态 |
| `POST /api/voices` | 上传录音和文字、创建音色 |
| `PATCH /api/voices/:id` | 改名或停用 |
| `GET /api/voices/:id/audio` | 试听原参考录音 |
| `POST /api/voices/:id/previews` | 创建合成试听任务 |
| `GET /api/voices/:id/previews/:previewId` | 查询进度及试听音频地址 |
| `GET /api/tts/config?projectId=…` | 当前项目服务、模型与健康状态，不返回密钥 |

写接口沿用同源校验，校验 ID、请求体大小、文本长度和录音解码结果。浏览器不直接接触本地服务令牌。此版仍按现有本机单用户工具定位，远程公开部署需另行设计账号与授权。

## 6. 怎么判断做好了

1. 独立环境能安装，模型能加载；记录总下载量、首次加载耗时、内存及 100 字中文冷/热生成耗时。实际生成 WAV 能正常播放，报告听感与速度限制，不承诺实时。
2. 上传两个不同的参考音色；重启服务和网页后仍可选择，分别生成同一句中文并试听，确认音色差异及可懂度。
3. 覆盖文件超限、伪造音频、长度超限、缺文字、服务未启动、超时、停用音色、路径越界等错误，不留下可用状态的坏音色或半成品。
4. 在真实网页完成：创建课程 → 应用 AI 草稿 → 选择本地音色 → 全部生成 → 试听 → 导出带声音 MP4；验证音频时长和画面同步。
5. 修改一节讲解稿/语速/音色，只有受影响内容要求重做；切换厂商后不能误用另一厂商的缓存。入队后切换厂商，原任务仍用原引擎。
6. 原有腾讯云、MiniMax、AI 写稿和导出检查继续通过，更新 README 和 `docs/操作指南.md`，写清初始化、日常启动和音色管理步骤。

真实运行验证先用自建测试项目，不改用户课程；需要新参考音色时通过正常上传入口加入。若当时没有可用真人录音，只能报告对应真实音色验证未完成，不能用协议模拟代替音质验收。
