# AI 教学视频项目目录结构建议

日期：2026-11-24

状态：目录设计建议。本文中的应用文件和目录尚未初始化；本次仅新增此文档。

依据：[AI 教学视频 Web 应用方案建议](../../AI教学视频Web应用方案建议_2026-11-24.md)。

## 1. 先确定组织方式

建议直接以当前 `AI_create_vidio` 文件夹作为项目根目录，采用一个仓库、一个 Node.js / TypeScript 项目。

第一版使用两个运行进程：

- **Web 进程：**提供页面、接收操作、查询进度。
- **Worker 进程：**在后台执行配音生成、时间对齐和视频导出等耗时任务。

Worker 就是“后台干活的程序”，不需要一开始就建立独立后端仓库。两个进程可以复用同一套业务代码，但 Web 进程不承担长时间的视频导出。

另一种做法是现在就拆成多个应用和共享包。它适合团队分工和独立部署需求明确以后，当前会增加配置、依赖与启动成本，因此第一版先采用上面的简单结构。

## 2. 推荐目录总览

以下是目标结构，不要求一次性创建全部空目录。随对应功能开发逐步建立即可。

```text
AI_create_vidio/
├─ docs/                         # 项目文档
│  ├─ architecture/              # 架构与目录设计；本文件所在位置
│  ├─ plans/                     # 后续确认的开发计划
│  └─ research/                  # 后续新增的调研资料
│
├─ src/                          # 应用源代码
│  ├─ app/                      # Next.js 页面和 HTTP 接口入口
│  │  ├─ layout.tsx             # 网页的公共外框
│  │  ├─ page.tsx               # 首页或项目列表入口
│  │  ├─ projects/[projectId]/  # 某条教学视频的编辑页面
│  │  └─ api/                   # 创建项目、启动任务、查询进度等接口
│  │
│  ├─ features/                 # 按功能组织的网页界面
│  │  ├─ projects/              # 项目列表、新建项目
│  │  └─ editor/                # 小节列表、讲解编辑、预览、配音和导出面板
│  │
│  ├─ components/               # 通用网页组件，如按钮、对话框
│  ├─ shared/                   # 浏览器和服务端共同使用的数据定义与校验
│  │  ├─ lesson.ts              # 一条教学视频的数据格式
│  │  ├─ scene.ts               # 一个小节及其画面、讲解和同步数据格式
│  │  └─ job.ts                 # 后台任务的类型、状态和结果格式
│  │
│  ├─ video/                    # Remotion 教学画面；预览与导出共用
│  │  ├─ index.ts               # Remotion 注册入口
│  │  ├─ Root.tsx              # 注册可导出的视频
│  │  ├─ LessonVideo.tsx        # 将多个教学小节组合成整条视频
│  │  ├─ scenes/               # 标题、代码讲解、流程图等小节画面
│  │  ├─ components/           # 视频内复用的字幕、箭头、高亮等元素
│  │  ├─ animations/           # 根据视频时间计算动画状态
│  │  └─ timeline/             # 将音频时长、停顿和动作安排换算为播放时间
│  │
│  ├─ server/                   # 仅服务端执行的代码
│  │  ├─ projects/             # 项目创建、保存、读取等业务
│  │  ├─ scenes/               # 小节修改、排序、版本和失效状态管理
│  │  ├─ agent/                # 理解要求、安排工具调用
│  │  │  ├─ tools/             # Agent 可调用的业务操作
│  │  │  └─ prompts/           # 教学规划、讲解和修改要求等提示内容
│  │  ├─ providers/            # 对接外部服务
│  │  │  ├─ llm/               # 文字模型
│  │  │  └─ tts/               # 配音服务
│  │  ├─ workflows/            # 生成讲解、配音、对齐、导出的步骤安排
│  │  ├─ jobs/                 # 任务持久化、领取、进度、失败和重试
│  │  ├─ rendering/            # 调用 Remotion 输出视频
│  │  ├─ db/                   # 数据库连接、表定义和迁移文件
│  │  └─ storage/              # 文件路径、写入、读取与媒体访问
│  │
│  └─ worker/                   # 后台进程入口，调用 server 中的任务处理逻辑
│     └─ index.ts
│
├─ public/                      # 可以公开访问的固定资源，如已授权字体和图标
├─ examples/                    # 可提交的小型教学示例数据
├─ tests/                       # 后续随业务开发添加的关键验证
├─ scripts/                     # 开发辅助脚本
├─ data/                        # 运行数据：数据库、上传、音频和视频；不提交 Git
├─ .env.example                 # 配置说明与空值示例；不含真实密钥
├─ .env.local                   # 本机真实配置；不提交 Git
├─ .gitignore                   # 忽略运行数据、密钥和构建产物
├─ package.json                 # 依赖及 Web、Worker、Remotion 的启动命令
├─ tsconfig.json                # TypeScript 配置
├─ next.config.ts               # Next.js 配置
├─ remotion.config.ts           # Remotion 配置
└─ README.md                    # 项目介绍、配置与启动说明
```

根目录中已有的 Markdown 和 HTML 调研资料本次保持原位，避免已有链接失效。以后新增调研资料可以放在 `docs/research/`；如果将来整理旧文件，需要逐个移动并更新引用。

## 3. 最需要分清的五个位置

| 位置 | 一句话解释 | 例子 |
| --- | --- | --- |
| `src/features/editor/` | 给制作视频的人操作的界面 | 编辑讲解稿、试听按钮、小节列表 |
| `src/video/` | 最后会出现在视频里的画面 | 数组、箭头、代码高亮、字幕 |
| `src/server/` | 保存数据并执行制作业务 | 调配音 API、管理版本、安排导出 |
| `src/worker/` | 启动后台任务执行程序 | 持续领取任务，调用任务处理逻辑 |
| `data/` | 程序运行后产生的真实文件 | 数据库、MP3、MP4、上传资料 |

例如，“修改讲解文字的输入框”属于网页编辑界面；“观众看到的讲解字幕”属于视频画面。这两类组件分别管理。

## 4. 代码之间怎样配合

### 4.1 用户创建视频

```text
网页编辑界面
  → app/api 接收请求并校验
  → server/projects 保存项目
  → server/jobs 创建后台任务
  → Worker 领取任务
  → server/workflows 安排制作步骤
  → 调用文字模型或配音服务，保存结果
  → 网页查询任务状态并展示结果
```

### 4.2 网页预览与正式导出

```text
shared 定义的小节和播放数据
  ├─ 网页中的 Remotion Player → 加载 video/LessonVideo.tsx 预览
  └─ server/rendering         → 加载同一套画面代码导出 MP4
```

共用画面实现，有助于让预览与成片保持一致。

### 4.3 Agent 的位置

Agent 通过 `server/agent/tools/` 调用已定义的业务操作，例如：

- 为项目生成小节草稿。
- 更新某个小节的讲解。
- 为某个讲解版本创建配音任务。
- 为已确认的项目版本创建导出任务。

业务规则放在 `server/projects/`、`server/scenes/` 和 `server/workflows/` 中，网页按钮与 Agent 调用共用这些规则。

Agent 不直接随意修改数据库，也不直接拼接任意文件路径。

## 5. 运行数据怎样存放

建议第一版本地使用 SQLite 和本地文件，所有运行数据集中在 `data/`：

```text
data/
├─ app.sqlite                                  # 项目、版本、任务、文件记录
├─ projects/
│  └─ <projectId>/
│     ├─ uploads/                              # 用户提供的资料与素材
│     ├─ scenes/
│     │  └─ <sceneId>/
│     │     └─ revisions/
│     │        └─ <revisionId>/
│     │           ├─ narration.mp3             # 该版本的配音
│     │           ├─ alignment.json            # 句子或动作的时间信息
│     │           └─ preview.png               # 可选的小节缩略图
│     └─ exports/
│        └─ <renderId>/
│           ├─ video.mp4                      # 成片
│           └─ manifest.json                  # 此次导出使用的版本和参数
├─ cache/                                     # 可复用的渲染或媒体处理结果
└─ temp/                                      # 制作过程中的临时文件
```

### 5.1 数据库和文件各管什么

- **SQLite：**保存项目内容、小节顺序、画面配置、版本、音频时长、任务状态和文件标识。
- **文件目录：**保存上传资料、音频、图片和视频等实际文件。
- **导出清单：**记录成片使用的小节版本、配音文件和输出参数，便于排查与复现。

项目内容以数据库记录为准，不在多个 JSON 文件中重复维护可编辑内容。`alignment.json` 和 `manifest.json` 是制作结果或导出记录。

路径使用系统生成的 ID，用户输入的课程标题只作为显示名称。

### 5.2 为什么需要版本目录

用户修改第 3 小节时，旧任务可能仍在执行。若所有结果都写入同一个音频文件，旧任务完成后可能覆盖新内容。

因此，每个任务绑定明确的小节版本，结果写入对应版本目录。旧任务结束后，只更新它自己的记录；只有当前版本匹配时，网页才将其显示为当前有效结果。

只改画面时，可以继续引用仍有效的配音；修改朗读文字或音色后，需更新配音，并重新计算受影响的时间安排。版本目录不要求重复复制所有未变文件。

### 5.3 用户数据与公开资源分开

`public/` 放应用自带、可公开访问的固定资源。

用户上传资料与生成结果保存在 `data/`，通过服务端媒体接口访问。浏览器预览与后台渲染需要把同一文件标识解析成各自可访问的媒体地址，不能把 Windows 本地磁盘路径直接传给浏览器播放。

## 6. 必须保持的代码边界

### 浏览器可用的代码

`shared/` 和 `video/` 保持可在浏览器中运行：

- 不读取数据库或本机文件系统。
- 不读取模型 API Key。
- 不导入 `server/` 或 `worker/`。
- `video/` 根据传入的内容和时间计算画面。

网页界面通过受控接口访问业务数据。

### 仅服务端使用的代码

`server/` 统一管理数据库、文件系统、模型密钥和外部调用，使用明确的服务端导入边界。

`worker/index.ts` 保持为薄入口，调用 `server/jobs/`，避免再复制一套业务逻辑。配置加载应保证 Web 与 Worker 使用同一份配置约定。

### 时间安排只有一套

画面停留、音频长度、字幕与动作的安排统一放在 `video/timeline/` 等共享计算代码中。服务端在配音完成后调用同样的计算规则，网页预览与导出读取相同的结果。

## 7. 第一版数据的核心概念

| 概念 | 含义 | 主要内容 |
| --- | --- | --- |
| Project / Lesson | 一条教学视频及其制作项目 | 主题、受众、输入资料、小节列表 |
| Scene | 一个教学小节 | 稳定 ID、顺序、当前版本 |
| SceneRevision | 一个小节的某次内容版本 | 朗读文字、屏幕文字、画面配置与动作 |
| Asset | 一个文件或制作结果 | 文件标识、类型、位置、来源版本、时长 |
| Job | 一次后台制作任务 | 输入版本、状态、进度、结果、失败原因 |
| RenderManifest | 一次导出的固定输入清单 | 小节版本、素材引用、尺寸和帧率 |

以上是建议的数据边界，不是最终数据库表结构。具体字段和关联应在功能设计时确定。

第一版 AI 输出优先使用可校验的小节数据和受控画面组件。若后续支持自由生成代码，用户生成的代码作为项目文件保存并隔离执行，不自动写入应用的 `src/video/`。

## 8. 第一阶段先建立哪些部分

先把“编辑内容 → 预览 → 保存 → 导出”做通，再接入付费模型服务：

1. 初始化 Next.js 与 Remotion，准备一个手写的教学示例。
2. 定义 `shared/scene.ts`，让编辑界面和视频画面使用相同的数据格式。
3. 实现项目列表、编辑页面和 SQLite 保存。
4. 建立后台任务与导出，验证导出后仍可继续编辑项目。
5. 接一家配音服务，根据真实音频时长调整画面。
6. 接文字模型与 Agent，生成和修改小节内容。

这一顺序可先验证制作底座，避免同时排查页面、模型、配音和视频输出四类问题。

### 第一版重点验证

- 编辑数据能够保存并恢复。
- 同一份小节数据在预览与导出中一致。
- 配音时长变化后，画面时间正确更新。
- 后台任务不依赖网页持续打开。
- 旧任务不会覆盖新版本。
- 修改一小节时，未受影响的结果能够复用。

## 9. 文档与源码管理

- `docs/architecture/`：放已形成的设计与决策。
- `docs/plans/`：放确认后的分阶段实现计划。
- `docs/research/`：放新增调研，避免与当前实现说明混淆。
- `examples/`：只放小型、可公开的示例输入；真实用户资料不放这里。
- `tests/`：随功能增加关键业务验证，不为每个空目录建立形式化测试。
- `README.md`：说明如何配置、分别启动 Web 和 Worker、运行示例与导出视频。

后续 `.gitignore` 至少应覆盖：

```gitignore
node_modules/
.next/
data/
.env*
!.env.example
coverage/
```

Remotion 打包输出、日志和测试临时结果的忽略路径，在确定实际构建命令后补充。真实密钥、上传资料、SQLite 数据库和生成的音视频不提交 Git。

## 10. 依据与说明

- [Next.js 项目结构](https://nextjs.org/docs/app/getting-started/project-structure)：`src/app`、页面和接口入口的框架约定。
- [Remotion Player](https://www.remotion.dev/docs/player)：在网页内嵌入视频预览。
- [Remotion 服务端导出接口](https://www.remotion.dev/docs/renderer/render-media)：程序化输出视频。

除框架约定外，上述业务目录和数据管理方式是针对本项目的设计建议，并非官方要求。
